范围：八爪鱼、墨鱼、鱿鱼的正常页面手势结果。复验者未阅读这三只伙伴的实现源码。主代理说明本组截图来自无 `audit` 的正常路由及真实浏览器指针操作；本复验逐张判断保存的实际画面，不以模型内部角度或断言代替画面。

已查看 18 张：每只的 `gesture-front`、`gesture-left`、`gesture-right`、`gesture-果冻-accessories`、`gesture-机械-accessories`、`vertical-no-turn`。下列判断只覆盖图片可见状态，不能单凭静止截图宣布完整手势轨迹无问题。

## 由独立复验者指定的黑盒反例

为避免只接受实现者自行选择的截图，复验者在查看既有结果之外，指定墨鱼的以下操作及预期，由主代理仅作内置浏览器操作员。

浏览器 API 当前只支持一段完整 `drag`，不能分离 pointerdown/move/up 或在截图时保持按住。因此本轮不冒充执行“同一次手势中横向—竖向—反向”的连续路径；改为三个独立手势：

1. 正常路由进入墨鱼，恢复原状，选择果冻与眼镜。在头部上半部单段向右拖约 120 CSS px，松手等待 1 秒，保存 A。预期形成明显侧向，眼镜跟随。
2. 在 A 的侧向状态重新抓住头部，保持屏幕 x 不变，单段竖直向上拖约 100 px，松手等待 1 秒，保存 B。预期朝向与 A 基本一致，不因高度变化继续转向。
3. 重新抓住当前最外侧长捕食触手末端，单段向左拖约 120 px，松手等待 1 秒，保存 C。预期被抓附肢响应，但不能把这次附肢横拉解释成头部转向。
4. 再等 3 秒保存 D 与页面 AX。预期停止抓取、形态恢复，眼镜贴合，保留最后合法朝向。

操作员已按上述指定返回 [A](blackbox-cuttle-A.png)、[B](blackbox-cuttle-B.png)、[C](blackbox-cuttle-C.png)、[D](blackbox-cuttle-D.png)、补充 [C2](blackbox-cuttle-C2.png) 及 [AX](blackbox-cuttle-AX.txt)，复验者已逐张独立查看。

| --- | --- |

| B：当前头部 `(570,470) → (570,370)` | 通过：保留 A 的右前朝向，未因竖直拉动变成正面、背面或另一侧；眼镜与脸共同移动，没有留下脱离的镜框或眼球。 |

本轮独立指定操作已验证“头部横拖可转向”与“已侧向后竖直拖动不误转”的黑盒结果，不只接受实现者原先选片。附肢横拖反例的命中与响应仍未形成充分独立证据；截图没有显示异常，不等于该反例已经通过。

单段截图能复核动作后朝向与恢复结果；无法观察同一次手势内的连续保持帧仍明确列为未验证，不以其他数值测试冒充真实指针连续画面。

## 首轮结论（保留失败记录）

三只伙伴左右侧向在正常交互结果中均可辨，已有竖直拖动结束截图未见误转。独立指定的墨鱼头部横转、侧向竖拉与可见恢复结果通过。现有图片没有显露脸部或附肢脱离；鱿鱼帽檐局部穿插未关闭。附肢横拖反例的可靠命中及同一次手势连续保持帧仍未验证，本文件不宣布正常手势整体全部通过。
