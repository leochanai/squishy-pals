# 质量门禁

产品预期由 [PRODUCT](PRODUCT.md) 裁决；模块边界、现有测试及命令见 [ARCHITECTURE](ARCHITECTURE.md)。本文件规定需要什么证据，不复制角色参数、设计规则或局部测试阈值。

## 风险裁剪

| 等级 | 适用改动 | 最小证据 |
| --- | --- | --- |
| L0 | 纯文档、注释、无行为影响的纠错 | 对照事实源，检查引用、命令与最终差异；无需启动应用 |
| L1 | 边界清楚的局部逻辑或单个控件 | 相关静态检查和定向测试；影响可见交互时补局部运行观察 |
| L2 | 伙伴扩展、核心操作、共享输入、切换、材质或主要布局 | 相关模块测试、类型检查和构建，覆盖受影响用户流程及边界；核心旅程做独立黑盒复核 |
| L3 | 跨模块大改、渲染后端、资源生命周期、平台支持或发布验收 | L2 加受影响角色、设备、错误恢复和长时间/快速重复操作的风险覆盖；检查真实构建或发布目标 |

验证范围由影响面决定，不要求每次跑全部角色与全部脚本。修复至少覆盖当前失败、相邻场景和可能被误伤的反例。检查通过后，只有新改动、失败或未解决风险才触发追加验证。

## 不得跳过的适用门禁

**P0：语义和结果正确。** 入口、当前选择、执行对象、场景与反馈一致；显式选择不得被默认值或过期异步结果覆盖。不同控制项的语义保持独立，切换、取消、失败与重置符合产品承诺。不得静默丢失应保留的状态，或未经授权改变数据与外部资源。

**P1：核心任务可用。** 正常流程、加载、失败、重试、禁用和取消按影响面覆盖；输入与反馈对应，键盘焦点及触屏操作可用。窗口、画布、设置区、滚动区边界清楚，关键控件和内容不被遮挡。共享机制变化需核对受影响角色的拾取、形变、回落、切换和资源释放，不能用一种角色代表所有结构。

**P2：视觉与平台品质。** 在语义和可用性成立后检查层级、可读性、视觉连续性及动效。持续妨碍主任务的布局、对比度或渲染问题属于 P1，不能降为装饰问题。

## 三条验收轨道

- **语义轨**：从任务入口到实际结果检查上下文、状态保留、默认值、重置、兼容与失败恢复。类型检查、构建或内部数值变化不单独证明用户结果成立。
- **交互轨**：在真实运行产品中操作受影响路径，覆盖鼠标、适用触屏、键盘/焦点、指针取消或失焦，以及必要的重复操作。静态截图不能代替操作。
- **视觉轨**：在真实浏览器的代表性桌面、手机及最窄受影响视口检查完整窗口、关键状态、滚动、可读性和无障碍。渲染变化还需观察动态形变、遮挡与材质；Node 几何断言、离线渲染图不能替代 WebGPU 画面。

三轨与 L0–L3 独立：每条记录通过、失败、未验证或不适用及理由。纯文档变更的交互/视觉轨可不适用；缺少 GPU、浏览器、时间或测试环境只能记为未验证。没有引入持久化的任务无需虚构保存、迁移或跨设备验收。

## 设计输入与校准

参考入口及已知范围见架构文档的「样式与参考输入」。文件存在或历史效果图不代表用户已批准本轮设计范围。

全新复杂界面、主要信息架构或视觉改版、高精度还原任务，在生产实现前核对用户指定或已批准的输入、适用范围、目标视口及关键状态；已有明确授权不重复确认。必要输入缺失时先完成独立部分，说明具体缺口；需要建立设计产物时交由外部设计流程，Harness 不代写。

这类任务分别保留实际读取的路径、版本或 Git ref、批准范围，以及输入约束了哪些实现的证据。运行后按相同视口、状态与代表性内容校准，区分缺陷和已确认偏差。局部小改仅核对受影响输入与画面，不机械生成完整设计评审。

对多个对象、视图或状态组成的交付，先依据产品契约列出必验矩阵，逐项对照参考与实际运行结果，不用合图总评或少量抽样代替明确要求的一一验收。每轮记录差异、影响、修复及同条件复查结果；共享实现修改后回查受影响项。必验项缺失证据不能标为通过，循环以标准满足或明确阻塞结束，不以迭代次数作为质量结论。具体伙伴与视角要求见 [新增伙伴成功标准](PRODUCT.md#新增伙伴成功标准)。

## 独立复核与完成结论

核心旅程或高风险交付，由未参与实现的评审者或具备新鲜上下文的独立 Agent，先依据产品目标和本轮任务契约，从真实入口进行黑盒复核。纯文档及低风险小改不强制独立浏览器验收。

证据留在任务结果、测试输出或相关制品中：记录环境/视口、入口与操作、预期与实际、可复核产物和未覆盖范围；不把逐次测试日志追加到长期 Harness。

- **通过**：适用 P0/P1 和匹配风险的验证均有证据，必要的独立复核完成。
- **有条件通过**：P0 和核心 P1 已通过，仅存在用户明确接受的非核心遗留，说明影响及后续动作。
- **失败或验收未完成**：P0/P1 失败或关键证据缺失。可报告已实现部分，不得声称对应功能或体验已完全完成。

未来新增门禁须能稳定约束多个功能。单个缺陷的方案、文件名、阈值和一次性风险应留在实现、测试或任务结果。
