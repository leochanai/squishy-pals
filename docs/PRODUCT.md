# Squishy Pals · 产品边界

本文依据现有 README、页面、角色实现及用户确认的要求，记录产品范围和交付标准；新增需求由用户当前任务裁决。

## 用户与目标

面向希望在浏览器里短暂放松、与软体动物互动的用户。打开图鉴、选择伙伴后即可捏、拉、戳，观察局部形变、弹跳和松手回弹，并调整外观与手感。

面向桌面和触屏浏览器，使用鼠标或触屏指针；按钮、材质选项和滑块保留各自的键盘操作。试玩所需浏览器能力见 [开发环境](ARCHITECTURE.md#开发与调试环境)。

## 当前范围与非目标

- 品牌首页、小伙伴图鉴及每个伙伴的独立试玩入口。
- 八爪鱼、墨鱼、鱿鱼、金鱼、鲸鱼、鲨鱼、海豹、海龟和螃蟹；可选角色由 [角色注册表](../src/characters/registry.ts) 管理。
- 按住按压、拖动身体或附肢、释放回落、专属动作及恢复原状。
- 每个伙伴四个颜色选项，软胶／果冻／机械材质，软硬与阻尼调节；佩戴与摘下饰品。
- 不支持账号、保存进度、跨设备同步、联网协作、用户上传或编辑模型。当前玩法为页面内即时体验，刷新或离开试玩后不承诺保留设置。
- 物理表现服务解压玩具手感，不以完整体积有限元模拟为目标；不承诺所有设备达到固定帧率。

## 核心用户流程

| 任务 | 入口与输入 | 可观察结果 | 失败、取消与恢复 |
| --- | --- | --- | --- |
| 找到并进入伙伴 | 首页进入图鉴，选择封面；也可直接访问伙伴链接 | 试玩伙伴与所选入口一致；名称与场景对应 | 未知伙伴返回 404；旧机械八爪鱼入口转到八爪鱼 |
| 捏拉与戳动 | 在当前伙伴身体或附肢上按住、拖动、松开；点击「戳一下」或在非控件输入场景按空格 | 按住局部凹陷，拖动产生柔性形变；释放后回落并逐渐稳定；戳动触发角色动作 | 指针取消或窗口失焦结束抓取；「恢复原状」回到默认状态 |
| 调整外观和手感 | 颜色、材质、软硬、阻尼、饰品控件 | 控件选择作用于当前伙伴；材质切换保留姿态、颜色、饰品，与软硬及阻尼相互独立 | 再次点击已佩戴饰品可摘下，「全部摘下」清空饰品；恢复原状清除自定义设置 |
| 连续切换伙伴 | 试玩页上方选择其他伙伴，可连续快速选择 | 最新选择最终生效；加载完成前仍能辨认当前显示的伙伴 | 加载时设置控件禁用；角色加载失败提供重试；引擎初始化失败显示设备能力说明 |

## 状态与操作语义

- 直接进入伙伴页使用该伙伴默认参数和正面姿态。切换伙伴时恢复新伙伴默认颜色、软硬、阻尼与姿态，并保留当前材质和饰品选择。
- 「恢复原状」恢复当前伙伴默认姿态、颜色、软胶材质、软硬及阻尼，同时摘下全部饰品。
- 饰品包括耳机、帽子、眼镜、蝴蝶结；帽子和蝴蝶结共用头顶位置，互相替换，其他位置可叠加。选项与互斥关系由 [饰品定义](../src/core/accessory-options.ts) 实现。
- 鱼类以及海豹、海龟、螃蟹的头部随横向拉扯连续转向，拉回手势起点恢复原朝向；仅点击、竖直拉动或拖附肢不应替代头部转向操作。
- 专属动作保留角色差异：海豹压扁弹起并扑鳍，海龟缩头探出，螃蟹举起双钳。共用「戳一下」入口不要求所有伙伴执行同一动作。
- 全局空格快捷键不能抢占滑块、按钮等控件的键盘行为。触屏拖动期间应操作伙伴，画布之外仍能浏览页面和设置。

## 新增伙伴成功标准

1. **先判断侧面需求。** 每个新增伙伴明确记录「需要／不需要侧面」及理由。正常拖动转向、专属动作会显露明显侧面，或关键物种特征需要侧面才能辨认时，必须纳入侧面支持与验收；不能因为侧面尚未做好而标为不需要。
2. **逐伙伴、逐视角对照。** 每个伙伴的正面必须通过；支持侧面的伙伴还须逐一检查侧面。左右结构或表现不对称时分别检查左右侧面。使用真实动物照片或可信形态资料，对照整体轮廓、身体与头部关系、附肢数量和位置、五官位置及物种特征；参考图需能支持对应视角的判断。具体萌化程度沿用用户确认的风格，保留物种辨识所需的结构。
3. **形成可复核的修复循环。** 每个必验视角保留「参考来源 → 当前实际渲染 → 差异判断 → 修复 → 同条件复查」证据，逐项关闭影响形态识别的差异。一个伙伴或一个角度通过不能代替其他必验项；几何修改后重查该伙伴所有必验视角，避免修好侧面又破坏正面。
4. **动态状态也成立。** 在必验视角下检查按压、身体及附肢拖动、专属动作和释放恢复；允许交互带来的弹性形变，但不能出现网格破裂、持续穿插、五官脱离或恢复后结构失真。
5. **与现有能力兼容。** 验证三种材质、颜色调整、软硬与阻尼、允许的饰品组合、伙伴切换和重置。材质或饰品不能掩盖基础形态问题；基础形态先在默认材质、无饰品状态下判定。图鉴封面和正面缩略图应与最终模型一致，并检查桌面、手机的取景及可操作性。
6. **明确退出条件。** 全部必验「伙伴 × 视角」及受影响交互通过，形态差异完成修复或得到用户明确接受，且对应检查有证据，才算添加成功。参考不足或环境无法验证时报告具体缺口，不能以已尝试多轮代替通过。

右侧工具栏不添加正面／侧面切换开关。验收视角通过模型已有接口、调试或截图流程设置；侧面支持不等于新增用户可见的视角控件。

## 成功标准

1. 从图鉴或直接链接进入的伙伴与试玩结果一致，连续切换不会被较早加载覆盖。
2. 在目标桌面和手机视口内，伙伴可见、可抓取，松手能回落；主要控制项可找到、可操作。
3. 外观与物理参数各自生效，切换及重置符合上述状态语义；场景与控件不能展示互相矛盾的结果。
4. 加载、不可用和失败状态清楚，用户能按当前可用路径重试或调整浏览器环境。

验收证据与风险裁剪见 [QUALITY-GATES](QUALITY-GATES.md)。本文不定义配色、构图或其他设计规则。
